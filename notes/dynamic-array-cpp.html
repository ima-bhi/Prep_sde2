Dynamic Arrays in C++ (std::vector)

Almost every NeetCode 150 problem hands you a vector<int>& nums and expects a vector back. These notes go from the basic syntax to how the vector grows in memory, so you can write array code quickly in an interview and explain its cost when asked.

Why it matters

A dynamic array is an array that grows when you add to it. In C++ it is std::vector. It stores elements next to each other in memory, like a plain array, so v[i] is O(1). Unlike a plain array, it tracks its own size and reallocates when it runs out of room.

  • LeetCode's C++ signatures use it everywhere: int maxProfit(vector<int>& prices), vector<vector<int>> threeSum(...).
  • You also use it as a stack, a frequency table, a DP table, a grid, an adjacency list and a visited array.
  • Interviewers ask follow-ups about it: why push_back is "amortized" O(1), and what happens to a reference after the vector grows.

Creating a vector

#include <vector>
#include <iostream>
using namespace std;               // fine in interview code, avoid it in header files

vector<int> a;                     // empty: size 0
vector<int> b(5);                  // {0, 0, 0, 0, 0}
vector<int> c(5, -1);              // {-1, -1, -1, -1, -1}
vector<int> d = {3, 1, 4};         // initializer list
vector<int> e(d);                  // copy of d
vector<int> f(d.begin(), d.end()); // from an iterator range
vector<string> words = {"go", "cpp"};
vector<long long> big(n, 0);       // use long long when sums can pass 2^31
Watch outRound brackets and curly braces mean different things. vector<int> v(5) is five zeros. vector<int> v{5} is one element, the number 5.

Reading and writing elements

vector<int> v = {10, 20, 30};

v[0];          // 10. No bounds check: v[10] is undefined behaviour, not an error
v.at(1);       // 20. Throws std::out_of_range if the index is bad
v.front();     // 10  (undefined on an empty vector)
v.back();      // 30  (undefined on an empty vector)
v[2] = 99;     // {10, 20, 99}

v.size();      // 3. Type is size_t, which is unsigned
v.empty();     // false. Prefer this over v.size() == 0

v.push_back(40);   // {10, 20, 99, 40}. Amortized O(1)
v.pop_back();      // {10, 20, 99}. O(1). Returns void, not the element!

int top = v.back();   // to "pop and use", read first...
v.pop_back();         // ...then pop

Looping

// 1. Index loop: use it when you need i (two pointers, prefix sums, neighbours)
for (int i = 0; i < (int)v.size(); i++) cout << v[i] << ' ';

// 2. Range-for by value: each x is a copy
for (int x : v) cout << x << ' ';

// 3. Range-for by reference: changes the vector itself
for (int& x : v) x *= 2;

// 4. Range-for by const reference: no copy, no changes. Best for strings and nested vectors
for (const auto& row : grid) { /* ... */ }

// 5. Iterators: what the STL algorithms use
for (auto it = v.begin(); it != v.end(); ++it) cout << *it << ' ';
HabitCast the size to int in index loops: i < (int)v.size(). It avoids signed/unsigned warnings and the empty-vector bug covered in Gotchas.

Passing vectors to functions

void byValue(vector<int> v);            // copies all n elements: O(n) per call
void byRef(vector<int>& v);             // no copy, and changes are seen by the caller
void byConstRef(const vector<int>& v);  // no copy, read-only. Your default for inputs

vector<int> build(int n) {              // returning by value is cheap (move or RVO)
    vector<int> res;
    for (int i = 0; i < n; i++) res.push_back(i * i);
    return res;
}
Common TLEIn recursion (DFS, backtracking), passing a vector by value copies it on every call. Pass it by reference and undo your change after the recursive call.
Level 2 · Everyday use

Insert and erase in the middle

Elements are stored side by side, so inserting or erasing anywhere but the end shifts every element after it. That costs O(n).

vector<int> v = {1, 2, 3, 4, 5};

v.insert(v.begin() + 1, 9);        // {1, 9, 2, 3, 4, 5}    O(n)
v.insert(v.begin(), 0);            // {0, 1, 9, 2, 3, 4, 5} insert at front: O(n)
v.erase(v.begin() + 2);            // {0, 1, 2, 3, 4, 5}    erase index 2: O(n)
v.erase(v.begin(), v.begin() + 2); // {2, 3, 4, 5}          erase range [first, last)
v.clear();                         // {} size 0, but capacity is kept
Interview tipIf you need to add or remove at the front a lot, use deque<int> (O(1) at both ends). If you only add at the back, build the vector backwards and call reverse once at the end.

size, capacity, resize, reserve

  • size is how many elements you have stored.
  • capacity is how many fit before the vector must reallocate. It is always ≥ size.
  • resize(n) changes the size. New slots are filled with 0 (or a value you pass).
  • reserve(n) changes only the capacity. It creates no elements.
vector<int> v;
v.reserve(100);     // capacity >= 100, size 0. v[0] is still undefined behaviour!
v.resize(3);        // size 3: {0, 0, 0}
v.resize(5, 7);     // {0, 0, 0, 7, 7}
v.resize(2);        // {0, 0}  (shrinking drops elements from the end)
cout << v.size() << ' ' << v.capacity();   // 2 100

v.shrink_to_fit();  // asks to drop unused capacity. A request, not a guarantee
Classic bugreserve(n) then v[i] = x writes into memory that isn't an element yet. After reserve, use push_back. After resize (or vector<int> v(n)), use v[i] = x.

Binary search helpers (on a sorted vector)

vector<int> s = {1, 3, 3, 5, 8};

auto lo = lower_bound(s.begin(), s.end(), 3);   // first element >= 3 -> index 1
auto hi = upper_bound(s.begin(), s.end(), 3);   // first element >  3 -> index 3
int first = lo - s.begin();                     // iterator -> index

Custom sorting with lambdas

vector<vector<int>> intervals = {{5, 6}, {1, 3}, {2, 4}};
sort(intervals.begin(), intervals.end());   // by [0], ties by [1]: {1,3} {2,4} {5,6}

// Sort by end time (Non-overlapping Intervals, Meeting Rooms)
sort(intervals.begin(), intervals.end(),
     [](const vector<int>& a, const vector<int>& b) { return a[1] < b[1]; });

// Sort by frequency (high first), then by value
unordered_map<int, int> freq;
for (int x : nums) freq[x]++;
sort(nums.begin(), nums.end(), [&](int a, int b) {
    if (freq[a] != freq[b]) return freq[a] > freq[b];
    return a < b;
});

// pair sorts by .first, then .second
vector<pair<int, int>> byDist;              // {distance, index}
byDist.push_back({5, 0});
byDist.emplace_back(2, 1);                  // builds the pair in place, same result
sort(byDist.begin(), byDist.end());
Comparator ruleReturn true only if a must come strictly before b. Use < or >, never <=. A <= comparator breaks sort's rules and can crash or produce garbage on inputs with equal values.

How a vector works inside

A vector object is small (24 bytes on a 64-bit machine). It holds three pointers into one block of heap memory: where the data starts, where the used part ends, and where the block ends.

What happens when it is full

  1. Allocate a new block, usually 2× bigger (GCC and Clang) or 1.5× bigger (MSVC).
  2. Move or copy every element into the new block. This is the O(n) step.
  3. Free the old block.
  4. Write the new element.
push 1 → cap 1
push 2 → cap 2 (copy 1)
push 3 → cap 4 (copy 2)
push 4 → cap 4
push 5 → cap 8 (copy 4)

Run this to watch it happen on your own compiler:

vector<int> v;
size_t lastCap = v.capacity();
for (int i = 0; i < 40; i++) {
    v.push_back(i);
    if (v.capacity() != lastCap) {
        cout << "size " << v.size() << " -> capacity " << v.capacity() << '\n';
        lastCap = v.capacity();
    }
}

Why push_back is amortized O(1)

One push_back can cost O(n) when it triggers a copy. But copies are rare, and they get rarer as the vector grows.

Push n elements with doubling. The copies happen at sizes 1, 2, 4, …, n/2, so the total copy work is 1 + 2 + 4 + … + n/2 < n. Add the n writes and the total is under 2n. Spread over n pushes, that is O(1) each on average. "Amortized" means exactly this: a guaranteed average over a sequence of operations, not over random inputs.

Likely follow-up: why multiply, not add?If the vector grew by a fixed +10 each time, it would copy at 10, 20, 30, …, n. That totals about n²/20 copies, which is O(n) per push. Only multiplying by a constant factor gives O(1) amortized.
Reserve when you know the sizeIf you know the final size, call res.reserve(n) first. It skips all the intermediate reallocations. Most of the time it doesn't change the big-O, but it's a cheap speed-up and shows the interviewer you know how vectors work.

Iterator and reference invalidation

The most common real vector bug, and a favourite interview question.

When a vector reallocates, its elements move to a new address. Every pointer, reference and iterator to the old block now points at freed memory.

vector<int> v = {1, 2, 3};
int& first = v[0];
int* p = &v[1];
v.push_back(4);        // capacity was 3, so this reallocates
cout << first << *p;   // undefined behaviour: both point into freed memory

// Wrong: adding to the vector you are looping over
for (int x : v) v.push_back(x);           // undefined behaviour

// Right: loop by index up to the original size
int n = v.size();
for (int i = 0; i < n; i++) v.push_back(v[i]);   // {1,2,3,4,1,2,3,4}
OperationWhat it invalidates
push_back, emplace_back, insert that reallocatesEverything: all iterators, pointers and references
push_back without reallocatingOnly end()
insert without reallocatingEverything at or after the insert point
erase, pop_backEverything at or after the erased position
reserve (if capacity grows), shrink_to_fitEverything

Erasing many elements: the erase–remove idiom

Calling erase inside a loop is O(n²), because every erase shifts the rest of the array. Instead, move the elements you keep to the front in one pass, then cut off the tail once.

// Remove all even numbers in O(n)
v.erase(remove_if(v.begin(), v.end(), [](int x) { return x % 2 == 0; }), v.end());

// Remove every 0
v.erase(remove(v.begin(), v.end(), 0), v.end());

// C++20 shortcut, same thing
erase_if(v, [](int x) { return x % 2 == 0; });

// Remove duplicates: sort, then unique, then erase
sort(v.begin(), v.end());
v.erase(unique(v.begin(), v.end()), v.end());

// If you must erase while iterating, use the iterator erase returns
for (auto it = v.begin(); it != v.end(); ) {
    if (*it < 0) it = v.erase(it);   // O(n) each time, so avoid this in hot loops
    else ++it;
}
This is a LeetCode patternremove doesn't actually erase anything. It moves the kept elements to the front and returns where the kept part ends. LeetCode 26 and 27 ask you to write exactly that by hand. See In-place write pointer.

Copy vs move

vector<int> a(1'000'000, 1);
vector<int> b = a;              // copy: O(n), now two million ints in memory
vector<int> c = std::move(a);   // move: O(1), c takes a's block. Don't use a's contents again

vector<vector<int>> res;
vector<int> path = {1, 2, 3};
res.push_back(path);            // copies path. Right for backtracking, since you keep changing path
vector<int> tmp = {4, 5};
res.push_back(std::move(tmp));  // moves tmp in. Use when you won't need tmp afterwards

Returning a local vector from a function never copies: the compiler moves it or builds it in place (RVO). So writing return res; is fine.

Gotchas that cost people interviews

1. size() is unsigned

vector<int> v;                              // empty
for (int i = 0; i < v.size() - 1; i++)      // v.size() - 1 wraps to 18446744073709551615
    cout << v[i];                           // reads way out of bounds

for (int i = 0; i + 1 < (int)v.size(); i++) { /* ... */ }  // safe
for (int i = 0; i < (int)v.size() - 1; i++) { /* ... */ }  // also safe: the cast happens before the - 1

2. vector<bool> is not a normal vector

It packs bits, so vector<bool> elements are not real bools and bool& b = vb[0] won't compile. It's fine for a visited array. If you need references to elements, or more speed, use vector<char> or vector<int>.

3. Out-of-range access fails silently

v[i] with a bad i may print garbage, crash later, or seem to work. While debugging, use v.at(i), or compile with -D_GLIBCXX_DEBUG (GCC) to get bounds checks on [].

4. Undefined on an empty vector

front(), back(), pop_back() and *max_element(...) on an empty vector are all undefined. Check empty() first, especially in stack problems.

5. clear() keeps the memory

clear() sets size to 0 but keeps the capacity. To actually free it: vector<int>().swap(v);

6. Integer overflow

accumulate(v.begin(), v.end(), 0) sums in int because the start value is an int. Use 0LL. The same applies to products and to mid = (lo + hi) / 2; write lo + (hi - lo) / 2.

Build your own dynamic array

This is NeetCode's Design Dynamic Array problem. Write it from memory once and the whole "Level 3" section will make sense.

Spec: DynamicArray(int capacity), get(i), set(i, n), pushback(n), popback(), resize() (double the capacity), getSize(), getCapacity(). Capacity starts above 0, and indices are always valid.

class DynamicArray {
private:
    int* arr;
    int size;
    int capacity;

public:
    DynamicArray(int capacity) : arr(new int[capacity]), size(0), capacity(capacity) {}

    ~DynamicArray() { delete[] arr; }

    // Copying would make two objects delete the same block, so forbid it
    DynamicArray(const DynamicArray&) = delete;
    DynamicArray& operator=(const DynamicArray&) = delete;

    int get(int i) { return arr[i]; }

    void set(int i, int n) { arr[i] = n; }

    void pushback(int n) {
        if (size == capacity) resize();   // full: grow first
        arr[size++] = n;
    }

    int popback() {
        return arr[--size];               // the slot stays allocated, it's just no longer counted
    }

    void resize() {
        capacity *= 2;
        int* bigger = new int[capacity];
        for (int i = 0; i < size; i++) bigger[i] = arr[i];   // the O(n) copy
        delete[] arr;
        arr = bigger;
    }

    int getSize() { return size; }

    int getCapacity() { return capacity; }
};
Follow-ups to be ready for Why double instead of +1? (Amortized O(1), see above.) When should it shrink? (At ¼ full, not ½. Shrinking at ½ means a push/pop/push/pop sequence right at the boundary reallocates every time.) How does the real std::vector differ? (It's a template, moves elements instead of copying them, and constructs elements only when they're added.)

In-place write pointer

Remove Element, Remove Duplicates, Move Zeroes

int removeElement(vector<int>& nums, int val) {
    int k = 0;                       // next slot to write
    for (int i = 0; i < (int)nums.size(); i++)
        if (nums[i] != val) nums[k++] = nums[i];
    return k;                        // first k elements are the answer
}

Vector as a stack

Valid Parentheses, Daily Temperatures, Car Fleet, Largest Rectangle

vector<int> res(n, 0), st;           // st holds indices
for (int i = 0; i < n; i++) {
    while (!st.empty() && temps[i] > temps[st.back()]) {
        res[st.back()] = i - st.back();
        st.pop_back();
    }
    st.push_back(i);
}

Bucket by count

Top K Frequent Elements (O(n), no heap)

unordered_map<int, int> freq;
for (int x : nums) freq[x]++;
vector<vector<int>> bucket(nums.size() + 1);
for (auto& [num, f] : freq) bucket[f].push_back(num);
vector<int> res;
for (int f = nums.size(); f >= 1 && (int)res.size() < k; f--)
    for (int num : bucket[f])
        if ((int)res.size() < k) res.push_back(num);

Prefix and suffix in the output array

Product of Array Except Self (O(1) extra space)

vector<int> res(n, 1);
int prefix = 1;
for (int i = 0; i < n; i++) { res[i] = prefix; prefix *= nums[i]; }
int suffix = 1;
for (int i = n - 1; i >= 0; i--) { res[i] *= suffix; suffix *= nums[i]; }
return res;

Backtracking path

Subsets, Combination Sum, Permutations, N-Queens

vector<vector<int>> res;
vector<int> path;
void dfs(vector<int>& nums, int i) {
    if (i == (int)nums.size()) { res.push_back(path); return; }  // copy
    path.push_back(nums[i]);     // choose
    dfs(nums, i + 1);
    path.pop_back();             // undo
    dfs(nums, i + 1);            // skip
}

Practice ladder

Do these in order. The first six train vector mechanics; the rest are NeetCode 150 problems where those mechanics matter. Ticks are saved in this browser.

    Self-check

    Answer out loud first, then open the card.

    What's the difference between size and capacity?

    Size is the number of elements stored. Capacity is the number that fit in the current memory block before the vector has to reallocate. Capacity ≥ size, always.

    Why is push_back O(1) amortized and not just O(1)?

    A push that finds the vector full allocates a bigger block and copies every element, which is O(n). Because capacity grows by a constant factor, those copies add up to less than n over n pushes. So the average stays O(1), even though one push can be O(n).

    You hold int& r = v[0], then call v.push_back(x). Is r still safe?

    Only if the push didn't reallocate, and you can't be sure of that unless you checked capacity. If it reallocated, r refers to freed memory, and using it is undefined behaviour. Either take the reference after the push, or store the index instead.

    What do vector<int> v(3) and vector<int> v{3} contain?

    v(3) is {0, 0, 0}. v{3} is {3}: braces prefer the initializer-list constructor.

    Why does for (int i = 0; i < v.size() - 1; i++) crash on an empty vector?

    v.size() is unsigned, so 0 - 1 wraps around to the largest size_t. The loop then runs far past the end. Cast first: (int)v.size() - 1, or write i + 1 < v.size().

    How do you remove duplicates from a vector?

    sort, then v.erase(unique(v.begin(), v.end()), v.end()). O(n log n) total. unique only removes adjacent duplicates, which is why you sort first. If the order must be kept, use an unordered_set to track what you've seen and copy into a new vector.

    When do you use reserve vs resize?

    Use reserve(n) when you'll fill the vector with push_back and know roughly how many items there will be. Use resize(n) (or construct with vector<int> v(n)) when you'll write by index with v[i] = x.

    Your backtracking solution gets TLE. What vector mistake is likely?

    Passing the path (or the input) by value to the recursive function, which copies it on every call. Pass by reference, push_back before recursing and pop_back after.

    Key points to remember
    • vector is a contiguous heap array plus a size and capacity. Index access is O(1).
    • push_back is amortized O(1) because capacity grows by a constant factor (×2 in GCC, ×1.5 in MSVC). Insert and erase in the middle are O(n).
    • Reallocation invalidates every pointer, reference and iterator into the vector. Never hold one across a push_back.
    • Pass inputs as const vector<int>&, mutable state as vector<int>&. Return vectors by value.
    • size() is unsigned. Cast to int before subtracting.
    • reserve sets capacity, resize sets size. Only resize lets you write v[i].
    • Remove many elements with erase–remove (one O(n) pass), not with erase in a loop.
