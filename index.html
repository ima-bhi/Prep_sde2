DSA

Count each problem once you have solved it on your own, without the video. Each card shows the week its category is scheduled for.

How to attempt each problem

  1. Read the problem and say the brute force out loud. Note its time and space complexity.
  2. Spend 25 minutes on your own attempt. Write down the pattern you think fits.
  3. Still stuck? Read one hint, then try for 10 more minutes.
  4. Only then watch CodeStoryWithMIK or the NeetCode video. Close it and code the solution from memory.
  5. Log it: the pattern, why you got stuck, and the date. Re-solve it after 3 days and again after 7.

JavaScript gotchas in interviews

  • JS has no built-in heap. Have a 30-line MinHeap class you can write from memory. LeetCode's JS runtime ships @datastructures-js/priority-queue, but most interview editors don't.
  • arr.sort() sorts as strings. For numbers, use (a, b) => a - b.
  • new Array(n).fill([]) shares one array across all slots. Use Array.from({length: n}, () => []) instead.
  • Use Map and Set for hashing. Object keys are always converted to strings.
  • Recursion overflows at roughly 10k frames. Use iterative DFS on big grids and graphs.
  • Numbers lose precision above 253. Use BigInt or a modulo when values grow that large.
Behavioral

Story bank

Write one real story for each prompt in STAR form: Situation, Task, Action, Result. Put numbers in the Result. SDE-2 interviewers listen for scope: decisions you drove, people you aligned, and impact you can measure. Your drafts save as you type.

Daily routine

Built around a full-time job. It's better to keep this pace every day than to do long sessions now and then.

≈ 2.5 h
  • AM 60–75mDSA: 2 problems from this week's NeetCode categories, using the attempt method.
  • PM 60mThis week's theory track: an HLD concept, an LLD pattern or the backend topic.
  • PM 15mRead yesterday's mistake-log entries. Say each solution's approach out loud.

≈ 4–5 h

  • 1.5hOne full design, start to finish: requirements, estimates, API, diagram, deep dives. Use Excalidraw or paper.
  • 1hBackend deep dive. Run something real, like an EXPLAIN plan, a Kafka consumer or a heap snapshot.

What you're preparing for

The SDE-2 backend loop

Most product companies run some version of these rounds. Each track in this plan maps to one of them.

DSA × 1–2

45–60 min each

One or two mediums, sometimes a hard. You're judged on clean code, testing it yourself and explaining complexity, as well as on reaching the right answer.

LLD / machine coding

60–120 min

Working, extensible code for a system like a parking lot or Splitwise. Common in Indian product companies. Interviewers check class design, patterns and how easily the design takes new requirements.

HLD

45–60 min

You lead: requirements, scale estimates, API, high-level design, then deep dives. At SDE-2 you're expected to defend trade-offs, not just draw boxes.

Backend deep dive

45–60 min

Your past projects, then Node internals, database choices, indexing, transactions, queues and failure handling.

Hiring manager / behavioral

45–60 min

Ownership, conflict, impact and mentoring. Amazon tests its Leadership Principles in every round, so map each story to two or three principles.
